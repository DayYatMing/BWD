Differences among following annotations:
@Component
@Service
@Repository
@RestController (vs. @Controller)

@Component - Generic Spring bean.
Use it when the class does not clearly belong to a specific layer.

@Service, @Repository, @Controller are specialized forms of @Component.
@Service
Used for business logic/service layer classes.

@Repository
Used for database access layer (DAO/repository layer).

@Controller
Used for web controllers / handling HTTP requests.

Note:
“Controller → Service → Repository is a logical separation, not mandatory technically.”

----------------------------------------------------------------------------------------------------

@bean scope
For non a web application, practically we mostly use singleton and occasionally prototype.
- Singleton, default, one instance of the bean is created per Spring container, stateless.
- Prototype (not commonly used), new instance is created every time the bean is requested, stateful, ie: ReportBuilder, PDFGenerator

For Web:
- Request, Each request gets its own bean.
- Session, Each logged-in user has their own cart.
- Application, One bean for the whole web application.
- WebSocket, Each WebSocket connection gets its own state.

For frontend, concept of component?
A component is a self-contained, reusable piece of UI that includes its own structure (HTML/JSX/etc.), styling, and often its own logic and state.

Purpose of spliting UI into components?
1. Reusability
2. Maintainability
3. Separation of concerns
4. Better scalability
5. Testability
6. Improved collaboration

Describe how a frontend request flow reaches the backend, reaches the database, and returns response.
Give details of each step as much as possible.

1. user action in the frontend.
2. request hits the backend controller - validation by DTO layer, such as @NotNull @Email @Size.
3. request continues on business logic layer, depends on the business logic and validation continues.
4. data access layer processes data based on the request.
5. database interaction proceeds, executes and returns result set if there is any.
6. result returns through repository, service, controller till frontend receives response.

In between services above, there are logging (logger), exception handling (global exception @ControllerAdvise), re-try, timeout to be implemented.
